- (constraint) User constraints: one web app, simple storage, mainstream docs-rich tools; examiner runs locally from README with no keys (Demo Mode, .env.example, test PDF); background processing survives page leave; established auth library; no committed keys; low AI cost; prompts as versioned files; evaluation and tests runnable from CLI; coaching, one question at a time; no commits
- (decision) Deliverables: spine + one-page plain-language explainer with simple diagram, reused in README and reflection report; audience is a programming newcomer/examiner. Coaching path.
- (decision) AD stack: Django (Python) server-rendered + htmx (no JS framework) + SQLite. Binds all pages/quiz/tabs/progress/status. Prevents second frontend language/build step. Accepted trade-off: quiz UX harder in Django; htmx covers instant feedback, tabs with saved progress, processing status, essay feedback. Why: user knows only Python, must read/review code. ADOPTED by user.
- (decision) AD background: DB-backed queue, exactly ONE worker, django-q2 with ORM broker on SQLite (workers=1). Every job idempotent (skip if result already stored; state transitions guarded). Binds: summary/quiz generation/essay feedback. Prevents: work tied to request, duplicate runs/double AI cost. ADOPTED.
- (decision) Library choice django-q2 over django-tasks DB backend: django-tasks docs warned of duplicate execution on SQLite (issue #33, unconfirmed fixed), package says breaking changes any time; Django 6 core tasks has no production worker. django-q2 mature, ORM broker, README lists Django 4.2-6.0 (sources conflict; verify at install, pin version; latest seen 1.8.0). Risk: SQLite 'database is locked' -> WAL mode + timeout.
- (decision) AD start: one cross-platform Python start script (run.py via 'python run.py') launches web server and qcluster worker, works on Windows, stops both on Ctrl+C. Demo Mode works without key. ADOPTED.
- (version) django-q2 1.8.0 (Apr 2025) latest seen; Django 6.0 released 2025-12-03 with core tasks API (no prod worker). Verify exact pins at install.
- (decision) AD ai-provider: ALL AI calls go through one file ai_client.py; rest of app never names the provider. Provider behind it: Google Gemini free tier (user has no key yet, cannot pay). Model name is a setting (env), never hardcoded. Client owns: structured-output validation (FR-27), 2 retries on bad output, rate-limit (429) waiting/backoff retries, cost/usage logging, stored-sample replay for tests. Evaluation runs paced to stay within limits. Provider confirmed by evaluation runs; on failed checks try larger Gemini model, else swap provider inside wrapper. ADOPTED.
- (constraint) Free tier: Google may use submitted data to improve products (official pricing table: free yes / paid no). Dev sends only builder's own/freely licensed slides. Upload notice (FR-6) MUST say this. PRD FR-6/UX copy currently says only 'sent to an AI service' -> PRD+EXPERIENCE follow-up needed. Free-tier limits changed Dec 2025 and can change again (unverified figures ~30 RPM/1000 RPD for Flash-Lite); not hardcode.
- (version) Gemini model names churn: sources conflict on 2.5 Flash/Flash-Lite shutdown (Oct 2026), Google staff recommend 3.1 Flash-Lite or 3.5 Flash for new projects; check ai.google.dev deprecations + pricing pages at build time and pick model then. SDK: google-genai (Python), structured output unverified, verify at build.
- (question) Open: PRD FR-6 and EXPERIENCE AI-notice copy must be updated for free-tier data use wording. Also: the examiner using own paid key vs free key -> notice text should depend on tier or be generic-worst-case.
- (decision) AD auth: django.contrib.auth with custom User model (AbstractBaseUser/AbstractUser), email as USERNAME_FIELD, set AUTH_USER_MODEL BEFORE first migration; this is build step 1. No verification, no reset (PRD). All ownership FKs point to settings.AUTH_USER_MODEL. Access control: every lecture/attempt query filtered by request.user; other-user -> 404. Example Lecture = public read-only, user=NULL. ADOPTED.
- (decision) AD pdf: pdfplumber (MIT) behind single function extract_pages(pdf)->list[str] (index = slide number-1, page==slide). Only that module imports a PDF lib. PyMuPDF ruled out (AGPL). Build order: after setup+custom user, first real step = FR-4 extraction test on a real PowerPoint-exported PDF; if messy, try pypdf on same file, keep cleaner per-page output; result recorded in repo (docs). ADOPTED.
- (decision) AD demo: Example Lecture loaded from repo data file (example_lecture.json) into the SAME tables, user=NULL, is_example=True; same screens/code. Rules: (1) ai_client demo/replay mode when no key: never calls out, prepared essay answers looked up from stored data, free typing off; (2) is_example rows immutable (no edit/delete), attempts on them stored in browser session only, never an account; (3) start script/setup loads example data on first run, fresh clone works with zero manual steps. Content provenance: made from builder's own or freely licensed slides, never course material; summary/questions/essay feedback come from a REAL AI run reviewed by builder, not hand-written; data file carries provenance metadata (generation date, model, prompt versions, reviewer, review notes). Demo auto-on when no key; 'Try the demo' always available. ADOPTED.
- (decision) AD prompts+eval: prompts/summary.md, prompts/questions.md, prompts/essay_feedback.md; header = version + changelog line (+ FR-10 plain-language instruction in body); named slots; loaded only by ai_client.py. Evaluation records version + content fingerprint (hash) of each prompt; refuses to run if text changed but version did not. Reports: evaluation/reports/YYYY-MM-DD-<n>.md with prompt versions, model name, results per check; run via 'python manage.py evaluate' (needs key, paced to rate limits, essay answers x3). Changelog of each prompt change names the report it was checked with (FR-30). ADOPTED.
- (decision) AD tests: Django built-in runner ('python manage.py test'); tests NEVER call real AI (ai_client replay of stored sample responses) and need NO .env file (settings must load with no env); each test name or comment states the FR/SM verified; includes deliberately broken AI responses (FR-27). ADOPTED.
- (decision) AD data: tables Lecture, SummaryPart, KeyTerm, Question, Attempt, Answer, EssaySubmission, Report (+Quiz status per lecture/type). JSON fields only for MC options and essay key points inside a Question row. Rules: (1) every user-owned row reaches user via FK; ALL queries scoped through owner (one rule for FR-2, 404 for others); (2) generated content immutable: summary/quiz written in ONE transaction, retries replace whole result, never edit in place; (3) Source References = list of ints validated vs page count before save; (4) Lecture.status uploaded->processing->ready|failed; Quiz status per type not_made->making->ready|failed, generated on first open then stored; (5) original PDF NOT kept after extraction, only per-page text stored (data minimisation); delete removes everything; reprocessing an old lecture requires a new upload (student keeps own slides). ADOPTED.
- (decision) AD setup+config: pip + venv + requirements.txt with EXACT pinned versions; run via 'python run.py'. Settings only in settings.py via django-environ from .env; .env gitignored; .env.example committed with every setting + comment; app AND tests start with no .env (missing API key => Demo Mode; missing SECRET_KEY => dev fallback only when DEBUG, else stop with clear message); test fails if .env is git-tracked or a key-like string is in committed files; no other module reads os.environ. README shows Windows commands first, Mac/Linux beside. Retry of failed processing works from stored page text when extraction succeeded; extraction failure needs new upload. ADOPTED.
- (version) Verify at install: django-environ current version and Django 6.0/5.2 support; pdfplumber, htmx, google-genai, django-q2 exact pins.
- (decision) AD status+progress: status via htmx polling every ~3s on a status view (reads DB status field); polling stops when Ready or Failed. Progress: every answer saved server-side on check/skip via small htmx POST; page rebuilt from DB on reload. Essay draft: autosave after ~2s pause + localStorage backup; server copy wins unless browser copy newer; localStorage draft backup CLEARED ON LOGOUT (shared computers). Example Lecture: same requests write to browser session. Failed save -> plain message, typed text stays on screen. ADOPTED.
- (decision) AD environment: local-only v1 (python run.py, SQLite file in project). README has short 'if you deploy this' section: DEBUG off, real SECRET_KEY, ALLOWED_HOSTS, HTTPS, persistent disk for SQLite, one worker, paid AI key, privacy review. Logging: console + rotating logs/recall.log with job events, AI call count/model, rate-limit waits; NEVER log lecture text, essay answers, passwords or keys. No backups in v1 (README says SQLite is the only copy). Daily upload limit (FR-7): counted per user per calendar day from a DB table, limit in a setting; rejected uploads (FR-3/4) do not count. ADOPTED.
- (decision) AD boundaries: apps by area (accounts, lectures [models/views/templates], plus plain modules ai_client, pdf_text, scoring). Rules: (1) views thin: request->call function->render; no scoring/matching/prompt text; (2) pure-logic modules (scoring, matching, review list, AI-output validation) import no Django models/request/network; (3) ai_client only importer of Gemini lib, pdf_text only importer of pdfplumber; (4) jobs call same service functions as views; status changes only via one set_status(); (5) import direction views/jobs -> services -> pure modules + two wrappers, never reverse. User reviews AI-written code against these rules. ADOPTED.
- (decision) AD ai-calls: one call per task with whole lecture text and page markers [Slide N]...[End slide N]; calls: 1 summary, 1 per quiz type (on first open), 1 per essay submission. Rules: structured JSON output with schema, then own validation, 2 retries (FR-27); lecture/essay text untrusted: prompts say marked content is data never instructions, no tools/links given to model, output only via validation into own tables; input-size guard in ai_client refusing oversized text with clear message; usage log per call (model, prompt version, approx tokens, wait; never content); essay answers length-limited (~3000 chars) and untrusted. ADOPTED.
- (decision) AD evaluation: two-step. 'evaluate' runs AI + automatic checks (structure, slide refs, key terms in text, one correct answer, essay ranking x3 runs) and writes evaluation/reports/ report with a review sheet (checkboxes: faithfulness, completeness, answer keys, source-ref spot checks) shown next to slide text; 'evaluate --finish <report>' refuses if boxes unticked, then prints final SM-10 pass/fail; 'evaluate --compare r1 r2' for FR-30. Test Set in evaluation/testset/ plain files with stored fingerprint, a test fails if frozen files changed (FR-26). Evaluation never runs inside manage.py test. Second AI as judge REJECTED (not independent; PRD makes builder the judge). ADOPTED.
