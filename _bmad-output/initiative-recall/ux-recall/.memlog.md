- (decision) Sources confirmed: brief-recall.md, prd-recall.md, tilbakemelding-product-brief.md. No existing sketches. Lecturer asks: sketches of upload, summary, quiz, results; accessibility for second-language students. Plus login. Wireframes as Markdown in repo. No commits.
- (decision) Stakes: coursework. Mood: calm, supportive, not exam-stressful; readability first (high contrast, very readable font, generous spacing). Colour theme B Soft indigo chosen: bg #F5F6FB, surface #FFFFFF, text #1B2033, muted #444B66, primary #3B4BA8, soft #E2E6F7, border #A9B0D6, ok #1B6B3A, err #A32D2D, focus #B36B00. Base 18px, line-height 1.6, Verdana/Segoe UI system stack. Status never by colour alone (icon+word).
- (decision) Second-language aids: IN = (1) key terms panel beside each summary part, (3) text size control, (5) icons always paired with a text label, never alone. IF-TIME = (2) tap/hover key term explanation inline. OUT = (4) interface glossary; instead keep UI words short and simple.
- (decision) Quiz feedback: MC and fill-gaps checked immediately per question, with link to source slides/summary part. Calm encouraging wording, no harsh 'wrong' signals (e.g. 'Not quite yet'); student moves on at own pace via explicit Next button (no auto-advance, no timer). Results page still shows total score + review list at the end. Essay: feedback after submit.
- (decision) Summary layout: one long page, 'Jump to' list at top, clear heading per Summary Part, key terms panel beside each part (below on phone). Review list entries, quiz source links and essay feedback deep-link (anchor) to the exact part.
- (decision) IA: top bar (logo, My lectures, Upload, text size, Log out; menu button with text label on phone). Lecture page is hub with tabs: Summary, Multiple choice, Fill in the gaps, Essay, Results. Requirements: quiz progress/answers kept when switching tabs mid-quiz; on phone tabs are a scrollable row with short labels (e.g. Summary, Choice, Gaps, Essay, Results).
- (decision) Processing: calm waiting screen with real plain-language steps (Reading your PDF / Finding the key points / Writing the summary), no fake percentage; auto-opens Summary when done. If student leaves, processing continues; lecture shows 'Processing...' in My lectures until ready. Failure: clear message + Retry (FR-5), no partial summary. Note for architecture: processing must be a background job, not tied to the page request.
- (decision) Essay: one question at a time, large text box, hint 'Write 2 to 5 sentences. Spelling and grammar are not marked.' Feedback below answer in 3 blocks: What you explained well / What is missing / Read this part again (link to summary part). Edit+resubmit allowed, max 3 attempts per question (cost + encourages rereading); earlier attempts and feedback stay visible. NOTE: PRD has no resubmit/3-attempt rule - needs PRD update (FR-17/FR-7 cost, Attempt definition, Essay Rating of which attempt counts for results/review list). Demo mode: prepared answers selectable.
- (decision) Results: last essay attempt counts for score and review list; results page lists every essay attempt (e.g. 'Attempt 1: 1 of 3 points, Attempt 2: 3 of 3 points') so progress is visible.
- (decision) Login: one centred card with tabs Log in / Register; short product line; visible labels; Show password checkbox; field-level plain-word errors; no Forgot password link; register tab note: 'We can't reset passwords yet. Please remember yours.' Prominent 'Try the demo' button on login page opens Demo Mode (example lecture) without registering or API key. NOTE for PRD: FR-23 says a visitor can open the example lecture, FR-2 says logged-out users get no lecture data - clarify that the example lecture is public/read-only and exempt from FR-2; also whether Demo works when an API key IS configured (button shown always?).
- (decision) Try the demo button always visible on login page (regardless of API key); demo banner on every demo page. Demo essay: prepared example answers selectable; free-text essay needs key. Next: Discovery wrap-up (anything else?), then draft spines + Markdown wireframes (wireframes/ folder).
- (decision) Extra: no timers/countdowns anywhere; UI text short literal sentences, no idioms/slang/jokes; minimal animation and honour prefers-reduced-motion; dark mode out of v1, on if-time list. Discovery closed; drafting spines + wireframes.
