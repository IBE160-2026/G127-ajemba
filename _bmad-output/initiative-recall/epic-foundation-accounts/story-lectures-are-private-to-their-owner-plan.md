## Intent

**Problem:** There is no Lecture table, so nothing yet guarantees that a student only ever reaches their own lectures (FR-2, SM-7), and nothing guards the import rules of AD-2.

**Approach:** Add a minimal `Lecture` model whose only door is an owner-scoped manager and a service pair (`get_lecture`, `get_lecture_for_write`). Add a stub detail page, a bare-404 for every wrong case, and two guard tests (generated URL-by-user test, import-boundary test). Add the README part.

## Boundaries & Constraints

**Always:** Views reach lectures only through `Lecture.objects.for_user(user)` (AD-8.1). A wrong user, a missing id and a write to an example row give the identical 404 (bare `Http404()`, no message, no id or title in the page). Logged-out requests go to login first, so they learn nothing about whether an id exists. Views stay thin and call services (AD-2). Tests name the FR/SM/AD they verify.

**Never:** Change login/register behaviour. Add upload, AI code or the Example Lecture exception (epic-demo-readme). Add tables other than `Lecture`. Download or install anything. Commit.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Owner reads | A requests own lecture | 200, lecture title shown | — |
| Other user | B requests A's id | 404, same page as missing id | no lecture data |
| Missing id | anyone logged in requests unused id | 404 | same page |
| Logged out | any lecture address | 302 to `/accounts/login/?next=…` | no lecture data |
| Example write | `get_lecture_for_write(user, id)` on `is_example=True` row | 404 | same page |
| Anonymous user object | `for_user(AnonymousUser)` | empty queryset | — |
| Import broken | module imports pdfplumber/Gemini/django_q outside its file | boundary check reports it | test fails |
